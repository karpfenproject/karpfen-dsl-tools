# 2.5 Using the library

karpfen-dsl-tools is the Kotlin library that reads, checks and writes the three modeling languages. The IDE and the
runtime are built on it, and a modeler who works in the IDE uses it without ever calling it. A programmer who wants to
handle karpfen texts in a JVM program of their own needs it, for example to check a project in a test or to build
models in code.

| Part | What it does |
|---|---|
| Readers | Read a KMeta, KModel or KStates text into a model. A reader never throws. It returns what it could build, every problem it found and where in the text each element is written. |
| Converters and printers | The converters read a text that is expected to be right and throw for one with errors. The printers write a metamodel, a model or a state machine back as text, as a whole or one element at a time. |
| Builders | Build a metamodel and a model in code, without a text. |
| Project verifier | Checks the state machines of a project against its metamodels and its model. |
| Flattener | Resolves the container states of a composition of [2.3.12 Pages](2.3-kstates.md#2312-pages) into one flat state machine and tells where each of its states was written. |

The problems that the readers and the verifier report carry the codes listed in [2.4 Checks](2.4-checks.md). A program
tells the reader of a state machine which of the [2.3.10 Optional features](2.3-kstates.md#2310-optional-features) a
text may use. Without a choice all of them are allowed. The library logs through the SLF4J API and brings no
logging backend of its own.

The library is published to GitHub Packages, from where a Gradle or Maven build takes it with these coordinates.

| Item | Value |
|---|---|
| Group and artifact | `io.karpfen:karpfen-dsl-tools` |
| Version | `2.0.0-SNAPSHOT` |
| Repository | `https://maven.pkg.github.com/karpfenproject/karpfen-dsl-tools` (GitHub Packages) |
| JDK | 21 |
| Dependencies a consumer gets | ANTLR runtime 4.13.1, `org.json`, SLF4J API |

GitHub Packages asks for credentials even for reading: a GitHub user and a token that may read packages. A build may
also take the library from a git submodule, as the runtime and the IDE do.

The complete description is the developer document
[Using the library from Kotlin](https://github.com/karpfenproject/karpfen-dsl-tools/blob/main/docs/library.md) on
GitHub. It names every class and function a program calls, explains what they take and return, and shows each of them
in a Kotlin example together with its output.
